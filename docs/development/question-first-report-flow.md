# 问题优先的六爻报告流程

更新日期：2026-09-06。范围：本地产品迭代，不代表生产发布验收。

## 用户流程

1. 直接输入问题。场景只用于可选的提问示例，不决定报告分类。
2. 真实模型先理解原问题与补充信息。含义明确时直接进入起卦和报告。
3. 只有会改变核心观察角色的歧义才追问，例如“加入”指入职还是投资。
4. 一个决定涉及收益、关系等多个顾虑，不强制拆开；求职和无关感情等独立问题，需要先选择本次处理的一件事。
5. 用户明确表示身份还没确定时，保留不确定性并分条件解释，不强行归类，也不循环追问。
6. 报告展示原问题、理解摘要、六爻盘面和真实 AI 解读。重复的起卦记录、角色分布和力量细节收起；顶部可直达解读。
7. “补充或纠正理解”沿用原卦、原起卦时间。旧版理解、依据和解读保留，更新后自动生成新版。

## 职责边界

| 内容 | 来源与约束 |
| --- | --- |
| 原问题、背景与纠正 | 用户输入；发送前隐藏常见手机号、邮箱和证件号，不宣称完成所有隐私识别 |
| QuestionProfile V2 | 真实模型结构化理解；不是已核实的现实事实 |
| 规则观察范围 | 选择已有支持的规则视角；不合适时使用 general:decision，不默认求职 |
| 六爻与历法 | 确定性引擎计算，不允许 AI 重排或改写 |
| AI 输入 | 完整六爻、历法、全部已命中 Findings 及 inputFacts、原问题、补充信息和理解边界 |
| 用户答案 | 真实模型生成直接回答、关键依据、现实意义、取舍和行动；不强套通用“继续小步验证”结论 |
| 事实与推断 | 空亡、旺弱、生克是盘面状态；不等于已核实合同缺失、对方敌意或现实没有变化 |

本次未新增无限场景模板，也未重新生成内容数据包。原有专题规则仍有覆盖边界，AI 不得把缺失规则写成已命中规则。

## 接口与版本

- `POST /api/v1/liuyao/questions/understand`：question、clarification，返回 understanding 和短期签名 token。
- `POST /api/v1/liuyao/charts`：携带问题、补充、token 和起卦输入。服务器重新验证理解与原文绑定，不信任客户端 topic 默认值。
- `POST /api/v1/reports/:id/understanding`：clarification、token、预期 revision。版本过期返回冲突，不覆盖新版。
- `POST /api/v1/reports/:id/ai`：生成当前理解下的真实解读；有效同版本结果复用。
- 问题提示词：`prompts/liuyao-question-v1.md`。报告提示词：`prompts/liuyao-report-v9.md`。

签名 token 绑定问题和补充原文，30 分钟有效。当前签名密钥属于 API 进程，重启后 token 失效，会重新理解，不影响已保存报告。当前限流与请求合并也是进程内实现。

历史版本保存在现有 Report.result JSON 的 interpretationHistory；当前版本为 interpretationRevision。无需新增数据库迁移。数据库 JSONB 字段排序不视为盘面变化。若实际爻字段因引擎版本不同而改变，拒绝原地更新，保留旧报告。

API 对同一报告更新加进程内互斥；worker 写回使用 updatedAt 条件，避免旧任务覆盖新版。多实例 API 的统一并发控制仍需生产化处理。

## 错误与质量检查

- 模型不可用或结构无效时明确报错，不用 mock 或模板冒充真实理解、真实解读。
- 补充已经选择了本次问题，模型却仍要求拆分时，发送纠正反馈重试；仍失败则保留输入并报错，不默默接受错误分类。
- 盘面字段不一致、证据引用非法、混入其他体系专属字段、虚构时间及不安全承诺仍为阻断项。
- 单凭出现术语无法判断是否已经解释。因此 V2 的术语匹配记录为 presentationWarnings，不再把整份解读标为模型不可用；可读性需要继续抽样评估。
- 页面“排盘字段一致性已校验”不表示已核实现实条件，也不保证每句自然语言推断正确。
- 失败重试保留当前表单；报告及历史需 DATABASE_URL 有效且实际返回 persistence=prisma。首页问题与补充信息支持当前标签 30 分钟草稿恢复，详见 `home-question-first-design.md`。

## 验证方法

```sh
pnpm run test:questions
pnpm run test:domain
pnpm typecheck
pnpm lint
pnpm run smoke:questions:live
```

真实冒烟测试需要 API、数据库和实际模型配置，消耗 API 额度并创建本地测试报告；不会删除已有报告。默认 API 为 `http://127.0.0.1:4100/api/v1`，可用 AI_SMOKE_API_BASE 调整。

覆盖求职、成立公司并经营、被动入股、歧义加入、未定身份、独立多问题、明确选择及一个决定的多个顾虑。完整流程验证 PostgreSQL 保存、纠正不改变原卦与历法、旧 AI 版本保留、新版生成和缓存复用。成功产物位于 `docs/audit/question-understanding-live-smoke.json`。

真实模型存在波动，单轮冒烟通过不等于全部场景达到发布标准。上线前仍需扩展真实问题语料的人工标注评测、事实到自然语言的蕴含检查，以及账户权限、分布式限流与并发验证。
