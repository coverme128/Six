# 首页与工作台 P0 修复记录

更新：2026-10-02。范围是匿名报告隔离、起卦事实、恢复与 AI 异常流程，不包括生产发布。

## 当前用户路径

- 首页六个场景仍是可选的问题示例，不作为用户必须选择的分类。
- 默认：输入问题，真实 AI 理解问题，记录一次六爻与 UTC 时刻，保存报告，报告页自动尝试真实解读。
- 已有卦：直接进入工作台，不等待模型；填写原起卦日期时间、时区和六个爻值。初爻与上爻有明确标注，并显示录入盘面的预览。
- 手动状态不再展示会切换到自动代摇的主按钮。切换方法、放弃草稿需要确认。
- 问题理解失败或暂停后，可以明确选择先保存盘面、稍后解读。保存的报告标记待理解，未伪造分类或 AI 答案；下次真实解读会先理解原问题和补充信息，再沿用原盘与时间解释。

## 草稿与重复提交

浏览器 `six-cast-draft-v2` 保存问题、补充信息、方法、六爻、时区、起卦时刻、请求编号与已创建的报告编号，最多保留七天。保存失败会提示用户，不能静默假装已保存。

提交前同步保存快照。服务端以匿名归属和 `requestId` 派生报告 ID；相同输入重试返回同一报告，已有请求编号携带不同事实返回 409。分类凭证和可用性变化不属于盘面事实，不改变报告编号。

报告创建后直接进入详情页，不再依赖第二次读取成功才保留编号。请求超时或取消不等于服务端已取消，恢复时必须使用原请求编号。

原时间在客户端转换为 UTC，同时保留时区。重复或不存在的夏令时本地时刻不猜测，要求改用 UTC。服务端请求必须带明确时刻，不能悄悄用提交时刻替代已有卦的原时间。

## 匿名记录的安全边界

- 浏览器生成 256 位随机令牌，以 `x-six-workspace` 请求头提交；服务端只保存其 SHA-256 归属摘要，不接受客户端传入 ownerId。
- 报告列表、详情、导出、AI、纠正理解、异步任务和删除均检查归属。没有凭证返回 401，其他人的报告返回 404。
- 清空只作用于当前归属，前端要求明确确认。
- 当前是浏览器匿名身份，不是跨设备账号。清除本站存储会丢失访问凭证；上线仍需 HTTPS、XSS 防护、网络层限流及备份。这些不应被误称为已经完成的账号体系。
- 问题理解按匿名归属限流；报告 AI 使用经过验证的归属，不再信任 body.deviceId 或固定 anonymous-web。IP 来源是服务端 request.ip，不直接相信任意转发头。

## 数据库升级与旧报告

新增迁移：`20261002080000_report_workspace`。只添加 nullable 的 `ownerId`、`requestHash` 和索引，不删除或自动分配历史报告。

在配置了正确 DATABASE_URL 的 SIX 环境中运行：

```bash
pnpm run db:generate
pnpm --filter @six/database exec prisma migrate deploy --schema prisma/schema.prisma
```

旧报告默认不可从匿名公共入口读取。管理员确认归属并备份后，在“我的报告 > 迁移旧报告”获取目标归属编号（不是密钥），逐个指定待迁入 ID：

```bash
node --env-file=.env --import tsx scripts/reports/assign-legacy-owner.ts \
  --owner-id TARGET_OWNER_HASH --report-id LEGACY_REPORT_ID
```

默认只预览；确认 ID 和归属无误后追加 `--apply`。已归属报告拒绝覆盖，批量操作在事务内完成。不能把所有旧报告自动归给第一个访问者。

- `pnpm run test:questions`：真实供应商适配器的隔离测试（测试传输替身，不进入产品），包括两个用户分别限流。
- `pnpm run test:home`、`pnpm run test:contract`、`pnpm run test:domain` 与 API/Web 类型检查。
- 浏览器实测包括手动入口无需模型、完整爻值和时间刷新恢复、保存原卦后自动真实解读、桌面与窄屏布局。
