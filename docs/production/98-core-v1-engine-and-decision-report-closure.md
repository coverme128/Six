# 98｜CORE_V1 引擎与决策报告 P0 收口

状态：`LOCAL_ACCEPTANCE_COMPLETE`  
范围：除生产发布外的本地实现与验收。

## 1. 本轮解决的问题

此前的 CORE_V1 数据加载完整，但运行时只消费了少量规则；报告因此可能出现关系方向错误、证据罗列多于综合裁决，以及 AI 解读与用户问题关联不足。本轮将数据加载、事实计算、条件化决策和 AI 表达拆成四层，AI 不再重新判断或修改专业事实。

## 3. 五行与动变方向

动变关系统一使用 `changed -> original` 作为回头作用方向：

- 变爻生原爻：回头生；
- 变爻克原爻：回头克；
- 原爻生变爻：化泄；
- 原爻克变爻：化克；
- 同五行：同气变化。

例如午火变戌土只能表达为“原爻午火生变爻戌土，原爻向变化方向泄力”，不得写成“变爻戌土生扶原爻午火”。该方向由引擎输出，AI 无权重新计算。

## 4. 决策报告事实层

`LIUYAO_DECISION_SUPPORT_V1` 在 AI 之前确定以下内容：

- 对用户问题的直接回答；
- 影响决定的场景维度；
- 可以继续推进的前置条件；
- 应暂停或保留的现实信号；
- 现在、条件明确时、作决定前的行动顺序。

求职与项目机会场景会分别检查机会、外部落实、书面条件、实际回报和自身承受力。其他场景按正式 Topic Role Registry 生成条件化决策结构，不将六亲术语直接作为一级用户语言。

## 5. AI 边界

DeepSeek 使用 `liuyao-report-v4`：

- `decisionSupportFacts.directAnswer` 是不可改写的受控结论；
- 模型只解释本卦、动爻、变卦和关键角色如何支持该结论；
- 模型输出中的直接回答与时间窗口在服务端再次规范化；
- 不允许新增规则、日期、概率、人物意图或保证性结论；
- 真实模型失败时保留确定性报告，不展示 mock 结果冒充真实解读。

## 6. 页面层级

报告默认阅读顺序调整为：

1. 直接回答；
2. 决策维度；
3. 推进条件与暂停条件；
4. 行动顺序；
5. AI 卦象因果解释；
6. 按需展开的角色、证据和专业盘面。

“本次解读口径”降为次级说明；支持/阻碍和专业角色默认收起，避免与首屏决策内容重复竞争。

## 7. 本地发布门槛

- Domain 全套测试通过；
- Web 与 API TypeScript 校验通过；
- 真实 DeepSeek 返回 `VALID`，且没有 deterministic fallback；
- 同一午火变戌土案例不得出现方向反转；
- 桌面与移动端报告首屏无溢出、遮挡或重复主结论；
- 生产发布仍需单独执行密钥轮换、线上环境变量、监控和发布审批。
