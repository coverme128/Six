# 首页核心体验与提问旅程 v2

最后复核：2026-08-18

状态：`IMPLEMENTED_AND_LOCALLY_VERIFIED`

## 1. 用户问题

旧首页不是功能缺失，而是价值层级失焦：

- “把问题转成可复核报告”描述的是系统工作，不是用户此刻能获得的帮助；
- 场景入口主要依靠文字区分，分类、图形和选中反馈不足；
- “推进趋势、冲突风险、保守边界”等词偏报告标签，用户需要再次翻译；
- 场景、可信机制、步骤、术法、问题和起卦方式同时出现，主任务不够集中；
- 问题输入上下都有同等级信息块，用户难以判断现在应该阅读还是行动。

## 2. 产品判断

首页首先是一项服务，而不是六爻技术说明页。用户来这里通常有两个核心意图：

1. 我有一件现实问题，希望看清方向和下一步。
2. 我还不准备起卦，希望先学习六爻如何工作。

因此第一屏只承诺可理解的价值：方向、关键点和下一步。确定性排盘、证据链和 AI 边界仍然重要，但属于信任验证层，应在用户准备生成报告时按需展开。

## 3. 设计依据

- GOV.UK Question Pages 建议将复杂表单拆成一次一个问题或决定，帮助用户聚焦当前任务：<https://design-system.service.gov.uk/patterns/question-pages/>
- GOV.UK Labels and Legends 建议每个页面围绕一件信息、一个决定或一个问题组织：<https://design-system.service.gov.uk/get-started/labels-legends-headings/>
- Material Design 3 要求选中、悬停和聚焦状态具有一致、可辨识且不只依赖颜色的状态反馈：<https://m3.material.io/foundations/interaction/states/overview>
- Nielsen Norman Group 的渐进披露原则支持先显示当前任务所需信息，再随用户行动展开更深内容：<https://www.nngroup.com/articles/progressive-disclosure/>

这些原则不是照搬视觉样式，而是用于约束首页的信息顺序和交互负担。

## 4. 新信息架构

### 第一屏：核心价值

```text
六爻问题分析
把一件难事，看清方向与下一步
方向 / 关键点 / 下一步
从我的问题开始 / 我想先学习
```

要求：

- 不在第一屏解释内部报告结构；
- 不把“可复核”作为用户必须先理解的概念；
- 使用真实视觉资产承载六爻的秩序感和分析感；
- 保留下一屏入口提示，避免第一屏成为封闭海报。

### 第二屏：场景选择

场景按用户寻找问题的自然领域分为 `感情与合作 / 工作与钱 / 生活事务 / 健康与纠纷`，一次只显示一组。分类不得混用使用频率、生活领域和风险等级等不同维度，也不得使用“谨慎”这类需要用户猜测含义的名称。每个分类至少承载两个可选择场景，避免 Tab 与唯一子项形成重复选择。每个场景同时使用：

- Lucide 语义图标；
- 跨色彩场景识别；
- 标题与短描述；
- 选中边框；
- 非颜色化勾选标记。

桌面端将选择反馈放在右侧同屏区域，移动端保持在当前分类选项之后。

### 第三屏：专注提问

只处理一个输入任务：写下此刻最想确认的一件事。

- 使用大尺寸多行输入框；
- 先帮助用户说清相关的人、当前情况和正在犹豫的选择，不以系统限制作为开场；
- 用“一次聚焦一件事”作为轻量提示，不使用“可行动的结果”等产品术语；
- 根据场景提供两个可点击示例；
- 示例带入后才启用继续按钮；
- 下一屏的起卦标题保持可见，形成自然任务接续。

### 第四屏：起卦与信任

默认只突出“开始起卦”这一个主动作。起卦前不展示六个空结果格，也不提前展示不可用的“生成报告”按钮。逐爻铜钱、数字铜钱和手动录入收进“更换起卦方式”，由有明确意图的用户主动展开。起卦完成后才展示六爻结果和“生成报告”；“重新起卦”作为低强调文字操作，不与当前主动作竞争。

可信机制在起卦前分两层呈现：用户必须知道的边界直接可见，即“排盘与判断依据不会由 AI 改写”；完整生成与复核机制按需展开。它既不应抢占选择场景和填写问题的注意力，也不能等到用户完成所有操作后才告知。

## 5. 文案标准

场景反馈使用用户会自然提出的问题，不使用内部栏目名称。

| 避免 | 使用 |
| --- | --- |
| 推进趋势 | 计划是否具备推进条件 |
| 冲突风险 | 手续、资金或时间哪里会卡 |
| 保守边界 | 什么时候调整更稳妥 |
| 结论方向 | 这次机会值不值得继续 |
| 协作建议 | 下一步怎样验证诚意 |

边界文案继续保留，但放在三个用户结果之后，以完整句表达，不作为并列标签。

## 6. 验收结果

- 1440x1000：首屏、场景同屏反馈和下一提问屏无横向溢出；
- 390x844：两层导航、首屏任务、双列场景入口和独立提问屏无横向溢出；
- 默认显示感情与合作分类，其中感情为第一入口；工作与钱显示 3 个场景，生活事务显示 3 个场景，健康与纠纷显示 2 个场景；
- 房产场景选择后显示自然语言的方向、卡点和行动结果预期；
- 示例问题可一键写入，继续按钮状态正确；
- 自动代摇完成后生成按钮可用；
- 选中状态同时使用边框、图标色和勾选标记；
- 起卦区默认只有一个主动作，其他方式按需展开；
- 未开始时不显示空六爻结果和不可用的报告按钮；
- AI 边界在开始起卦前直接可见，完整可信机制按需展开。

## 7. 后续约束

- 新增场景必须同时提供图标、用户问题示例、三条自然语言结果预期和专业边界；
- 场景分类必须统一使用用户事项领域，不得混用频率、风险等级或内部业务分组；
- 不允许把 `reviewStatus`、RuleCode、ViewModel、AI provider 或实现状态带回首页；
- 不允许通过增加首页说明文字来弥补交互不清晰；
- 新增步骤时优先评估是否应放入后续屏幕或渐进展开；
- 首页视觉回归必须覆盖桌面及 360/390/430 移动宽度。
