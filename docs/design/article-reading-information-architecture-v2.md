# 内容文章阅读信息架构 v2

最后复核：2026-08-19

状态：`IMPLEMENTED_AND_LOCALLY_VERIFIED`

## 1. 问题判断

旧文章页直接按数据包字段顺序输出内容，导致四类问题：

- 模板化 `subtitle` 被当作首屏价值说明，语言抽象且缺乏具体收益；
- 正文标题与段落连续堆叠，原因、方法、条件、案例和边界没有视觉层级；
- “在产品中的阅读、展开与复盘位置”等编辑实施说明被错误暴露给用户；
- 相关推荐只截取前六条，教程、知识卡和 FAQ 使用同一种卡片，类型不易识别，FAQ 还可能被排序截掉。

根因是内容数据结构被直接当作页面信息架构，没有经过用户阅读任务的转换。

## 2. 文章首屏

文章首屏固定展示：

1. 内容类型；
2. 用户可直接理解的文章标题；
3. 描述现实问题与文章收益的摘要；
4. 难度与核验状态；
5. 对应文章视觉。

数据包中的原始 `subtitle` 不再直接显示。首屏之后优先呈现最多四条关键结论，让用户在进入长文前先获得稳定认知框架。

## 3. 正文结构

桌面端采用目录与正文双栏，移动端改为单列。正文按语义拆分为独立章节，并使用“先理解原因、保留判断基准、确认是否有新条件、看一个具体例子、照着记录与复盘”等阅读标签。

以下内容不重复进入主正文：

- 与 `practicalFramework` 重复的章节；
- 与 `commonMisunderstandings` 重复的“常见误区”；
- 与 `knownLimitations` 重复的“使用边界”；
- 标题以“在产品中的”开头的内部编辑实施说明。

适用范围、停止条件、现实验证和使用边界默认折叠，用户需要时再展开。关键判断门槛与常见误区保持显性展示。

## 4. 相关内容发现

相关文章不再只在页面最底部出现。关键结论后提供明显的分段切换控件，知识卡、常见问答与延伸教程分别显示数量、图标和选中状态。用户选择后直接滚动到对应内容，并且文末只展示当前选择的一类内容。

文末按用户意图区分三种呈现：

| 类型 | 用户任务 | 展示形式 |
| --- | --- | --- |
| 知识卡 | 快速理解术语和概念 | 概念、名称、短定义卡片 |
| 常见问答 | 直接处理一个具体疑问 | 单行问题入口 |
| 延伸教程 | 沿当前主题系统阅读 | 带顺序和摘要的教程入口 |

每类只显示少量高相关内容，避免重新形成长列表：知识卡最多 3 张，FAQ 最多 4 个，教程最多 3 篇。

包含中文的内容 slug 必须在详情页请求前解码一次，避免二次编码造成知识卡或 FAQ 链接进入“未找到内容”。

## 5. 短条目与图片

术语和短知识卡不使用长文章模板。术语页只展示术语类型、名称、定义、难度与所属知识范围，随后直接进入相关概念；不显示“示例内容”“本文还配有”“下一步”等低价值模板文案，也不展示指向自身的重复概念卡。

文章首图和正文关键图示都支持点击放大。放大层提供明确关闭按钮，支持点击遮罩和 `Escape` 关闭，并在打开期间锁定页面滚动。

## 6. 验收标准

- 首屏不显示原始模板化 `subtitle`；
- 用户正文不出现 `CORE_V1`、资产 ID 或内部产品集成说明；
- 关键结论最多四条且首屏后立即可见；
- 正文主章节可从目录跳转；
- 重复章节只保留一种展示；
- 知识卡、FAQ 和教程在正文前段以明显分段控件出现，在文末有不同视觉形态；
- 中文知识卡与 FAQ 链接可以打开真实内容，不进入“未找到内容”；
- 术语页不复用文章 CTA 与文章资源说明；
- 可放大图片支持鼠标与键盘关闭；
- 360、390、430 和桌面宽度无页面级横向溢出。
